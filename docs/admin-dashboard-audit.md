# تدقيق لوحة إدارة مرج — 25 أغسطس 2026

## الغرض

> تجيب لوحة الإدارة عن سؤال: **ما الذي يحتاج قرارًا أو إجراءً من مسؤول متجر مرج اليوم؟**

المستخدم المستهدف هو مالك المتجر أو مدير التشغيل. المصادر المتاحة حاليًا هي الكتالوج والـ variations والطلبات وإعدادات المتجر فقط؛ لا توجد أحداث Analytics أو Refunds أو بيانات دفع من بوابة مرتبطة، ولذلك لا يجوز عرض Revenue أو Conversion Rate أو AOV أو Return Rate كمؤشرات فعلية.

## الأدلة الحالية

| المجال | الملاحظة | الدليل | الأثر | القرار |
|---|---|---|---|---|
| النظرة العامة | تعرض عدادات مباشرة للمنتجات والمسودات والمخزون والطلبات، ثم قائمة منتجات وإجراءات سريعة | `/admin`، desktop و390px | جيدة كنقطة بداية، لكن لا تجيب بوضوح عن ترتيب العمل | تحويل العدادات إلى قوائم عمل قابلة للنقر |
| المخزون | عداد المخزون الحالي يحسب المنتج إذا كان أي variation ≤ 3 أو حالة المنتج ليست متاحة | `admin.dashboard` في `server/routers.ts` | عبارة «منتج يحتاج متابعة» غير دقيقة عندما الخطر على variation محدد | إظهار product + size + color + quantity لكل variation معرض للخطر |
| الطلبات | جدول الطلبات يسمح بتغيير الحالة، لكنه بلا فلاتر أو فصل لطلبات تحتاج البدء/الشحن | `/admin/orders`، desktop و390px | مدير التشغيل يحتاج العثور على العمل العاجل قبل الأرشيف | إضافة فلتر حالة ورابط مباشر من overview إلى queue الفعلية |

| الإعدادات | نموذج واضح لإدارة الشحن والإرجاع وإفصاح الدفع | `/admin/settings` | يعطي تحديثات نصية لكنها لا تعني ربط بوابة حية | وضع العبارة بوضوح ضمن حالة تشغيل المتجر وعدم اختلاق integration |
| الهاتف | بطاقات overview تتحول إلى عمود وتظل قابلة للقراءة | `/admin` عند 390px | جيدة؛ لوحة الطلبات تحتاج filter واضحًا قبل الجدول | تفضيل queues وبطاقات موجزة قبل الجداول الكبيرة |

## النطاق المقترح

| يظهر الآن | لا يظهر حتى تتاح بيانات صحيحة |
|---|---|
| منتجات منشورة/مسودات، variations منخفضة/منتهية، طلبات حسب الحالة، آخر طلبات تحتاج إجراء، روابط الكتالوج والطلبات والإعدادات | المبيعات، الإيراد الصافي، التحويل، AOV، العائدات، إسناد الحملات، شركة الشحن/التتبع، المدفوعات الناجحة |

## ترتيب التنفيذ

1. إضافة summary مشتق من الطلبات والـ variations يعرض **queue التشغيل** و**مخزون variation المعرض للخطر** فقط.
2. إضافة فلترة حالة للطلبات والحفاظ على حالة الفلتر في الرابط، حتى تصبح بطاقات overview إجراءات لا أرقامًا للزينة.
3. إعادة ترتيب overview إلى: ما يحتاج إجراء → آخر الطلبات ذات الصلة → مخزون يحتاج متابعة → إجراءات الإدارة.
4. توثيق اختبارات summary وتحقق صلاحيات المدير وواجهة 390px.

## حدود معروفة

لا يوجد حجز ذري للمخزون أو اتصال دفع/شحن أو بيانات Analytics في المتجر حاليًا. لا يعالج هذا التحديث هذه التكاملات؛ سيعرض محدوديتها صراحة بدل إخفائها وراء مؤشرات غير مدعومة.
