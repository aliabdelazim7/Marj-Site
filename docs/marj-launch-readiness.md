# مرج — جاهزية الإطلاق وخطة التشغيل

**تاريخ المراجعة:** 25 أغسطس 2026  
**النطاق:** متجر «مرج» المستقل المبني بـ React/tRPC/Drizzle، للسوق المصري وبواجهة عربية RTL.

## الملخص التنفيذي

متجر «مرج» يملك رحلة تسوق أساسية مكتملة من الكتالوج المفلتر إلى صفحة المنتج، اختيار الـ variation، المفضلة، السلة، Checkout، تأكيد الطلب، تتبع الطلب، وحساب العميل. كما يوفّر لوحة إدارة لإدارة المنتجات والـ variations والمخزون والوسائط وصور `front` و`back` وأصول `GLB/GLTF` الاختيارية. إعدادات التشغيل المركزية تجعل نطاق الشحن ورسومه وحد الشحن المجاني وسياسة الاستبدال وإفصاح الدفع قابلة للتحرير من لوحة الإدارة.

> لا يجب فتح المتجر للطلبات الفعلية قبل إدخال حقائق كل SKU، ورسوم/مدة الشحن الفعلية، وسياسة الإرجاع المعتمدة، وطريقة الدفع التي ستُستخدم. لا يوجد Payment Gateway حي أو حجز ذري للمخزون في هذا الإصدار.

## الأدلة وحالة الجاهزية

| المجال | الوضع الحالي | الدليل داخل المنتج | الأولوية قبل الإطلاق | المالك | الحالة |
|---|---|---|---|---|---|

| صفحات المنتج | صفحة مستقلة، سعر/stock/variant وسلة وTry-On | `/product/:slug` | إدخال الخامة والـ fit والعناية والمقاسات الحقيقية | مالك المتجر | يحتاج حقائق SKU |

| الشحن | مصر كلها؛ الرسوم والحد المجاني قابلان للتعديل | `/admin/settings` وملخص السلة | إدخال رسوم ومدة ومناطق/استثناءات الشحن الحقيقية | العمليات | يحتاج تهيئة |

| الخصوصية | تجربة Try-On تطلب موافقة وتوضح معالجة الصورة | واجهة Virtual Try-On | مراجعة النص النهائي ومصدر أصول الذكاء الاصطناعي قبل التسويق | مالك المتجر | مراجعة أخيرة |

## أسئلة وحقائق لازمة من مالك المتجر

هذه المعلومات لا تُستنتج من التصميم أو الصور، ويجب إدخالها أو اعتمادها قبل إطلاق أي منتج:

| الفئة | البيانات المطلوبة | أين تُستخدم |
|---|---|---|
| هوية المنتج | اسم المنتج النهائي، SKU، الفئة، اللون، السعر، سعر التخفيض عند وجوده | الكتالوج والبحث والـ SEO |
| المواصفات | الخامة، الوزن/السماكة عند الحاجة، الـ fit، بلد/مكان التصنيع إن أُريد ذكره، التفاصيل الحقيقية | صفحة المنتج وخدمة العملاء |
| المقاسات | جدول قياسات حقيقي لكل variation، إرشاد fit، القياسات المرجعية للموديل إن استُخدم | صفحة المنتج وتقليل الاستبدال |
| العناية | تعليمات الغسيل والتجفيف والكيّ المطابقة للخامة والطباعة | صفحة المنتج وعمليات ما بعد الشراء |
| الصور | صورة front وback أصلية، لقطات تفاصيل/خامة عند الحاجة، alt text، وملف 3D اختياري | صفحة المنتج وتجربة الشراء |
| المخزون | كمية كل لون/مقاس، نقطة إعادة الطلب، مسؤول التحديث | variations والطلبات |
| الشحن | الرسوم، مدة التسليم المتوقعة، شركة الشحن، الاستثناءات، حد الشحن المجاني | السلة وCheckout وصفحة السياسات |
| الاستبدال والإرجاع | المدة، حالة المنتج المقبولة، الأصناف المستثناة، رسوم الشحن العكسي، مسار استرداد المبلغ | `/policies` وCheckout وخدمة العملاء |
| الدفع | الوسائل المقبولة، provider إن وجد، حالة الدفع عند الاستلام، خطوات الفشل/الإلغاء | Checkout ونصوص العميل |

## متطلبات بيانات SKU

يُستخدم قالب مفصل قابل لإعادة الاستخدام في [`marj-sku-intake-template.md`](./marj-sku-intake-template.md). يجب اعتبار الحقول التالية إلزامية قبل نشر SKU للبيع الفعلي: `sku` واسم المنتج والسعر وvariation والكمية والصور والـ fit والخامة والعناية وجدول المقاسات وحالة الأهلية للإرجاع. يظل أي وصف أو claim غير موثق خارج صفحة المنتج حتى يقدمه مالك المتجر.

## ترتيب التنفيذ قبل الإطلاق

| الترتيب | الإجراء | سبب الأولوية | معيار القبول |
|---:|---|---|---|
| P0 | إعداد رسوم ونطاق ومدة الشحن والنص النهائي لسياسة الإرجاع من `/admin/settings` | يمنع وعودًا غير صحيحة في Checkout | تظهر المعلومات المعتمدة نفسها في السياسات والسلة وCheckout |
| P0 | إدخال حقائق وصور front/back حقيقية ومخزون كل variation لكل SKU منشور | يمنع اختلاف المنتج أو المقاس أو التوفر عن الواقع | كل منتج منشور يملك checklist مكتملًا في قالب SKU |
| P0 | اعتماد طريقة الدفع وتشغيلها في Test Mode قبل Live | لا يجوز عرض دفع حي غير مهيأ | نجاح سيناريو دفع/طلب تجريبي وإلغاء/فشل واضحان |
| P1 | قرار تشغيلي للمخزون: مراجعة يدوية لكل طلب أو تطوير حجز/خصم ذري | يقلل مخاطرة بيع المخزون أكثر من مرة | إجراء موثق أو اختبار تكامل ذري |
| P1 | ربط Analytics provider بالـ events أدناه | يجعل التحسين قائمًا على قياس لا انطباع | ظهور event test في بيئة الاختبار من دون بيانات حساسة |
| P2 | استبدال الصور المفاهيمية الحالية بجلسة تصوير كاملة وإضافة 3D عند توفره | يحسن وضوح المنتج والثقة | صور موحدة، alt text، وتمييز أي generated concept |

## خطة القياس

لا تُرسل أي Events أو بيانات تسويقية حالياً من دون اختيار مزود تحليلات وموافقة المالك. عند اختياره، يجب أن تكون المعلمات أقل ما يمكن وألا تشمل صور Try-On أو العنوان أو الهاتف أو البريد الإلكتروني.

| Event | لحظة الإطلاق | المعلمات المسموح بها | مصدر الحقيقة | KPI المرتبط |
|---|---|---|---|---|
| `product_view` | فتح صفحة منتج منشور | `product_id`, `slug`, `category` | صفحة المنتج | Product-view rate |
| `catalog_search` | تنفيذ بحث في الكتالوج | `query_length`, `results_count` | صفحة المنتجات | Search success |
| `catalog_filter_applied` | تغيير فلتر أو ترتيب | `filter_type`, `filter_value`, `results_count` | صفحة المنتجات | Filter utility |
| `variant_selected` | اختيار لون/مقاس | `product_id`, `variant_id`, `size`, `color` | صفحة المنتج | Variant engagement |
| `add_to_cart` | نجاح الإضافة للسلة | `product_id`, `variant_id`, `quantity`, `unit_price` | CartContext | Add-to-cart rate |
| `checkout_started` | فتح checkout بسلة غير فارغة | `line_count`, `cart_value`, `shipping_value` | Checkout | Checkout-start rate |
| `order_created` | نجاح `orders.create` فقط | `order_number`, `line_count`, `subtotal`, `shipping`, `total` | Server order record | Orders and AOV |
| `stockout_seen` | محاولة variation غير متاح | `product_id`, `variant_id` | صفحة المنتج/Server validation | Stockout rate |
| `return_requested` | عند بناء سير عمل الإرجاع لاحقًا | `order_number`, `reason_code` | نظام الإرجاع | Return rate and reasons |

| المقياس | التعريف | الحساب | دورية المراجعة |
|---|---|---|---|
| Conversion Rate | نسبة الطلبات المنشأة من الجلسات | `orders / sessions` | أسبوعية |
| Add-to-Cart Rate | نسبة الإضافات مقارنة بمشاهدات المنتج | `add_to_cart / product_view` | أسبوعية |
| Checkout Completion | إتمام الطلب بعد بدء Checkout | `order_created / checkout_started` | أسبوعية |
| Average Order Value | متوسط قيمة الطلبات المنشأة | `sum(order_total) / orders` | أسبوعية |
| Stockout Rate | نسبة مشاهدات/اختيارات غير المتاح | `stockout_seen / variant_selected` | أسبوعية |
| Return Rate | نسبة الطلبات التي انتهت بطلب إرجاع | `return_requested / delivered_orders` | شهرية |

## قائمة تحقق النشر والرجوع للخلف

قبل نشر تغيير تشغيلي، راجع كل إعداد في Preview ثم اختبره بطلب تجريبي غير حقيقي عندما يكون ذلك ممكنًا. احتفظ بالقيمة السابقة لرسوم الشحن والسياسة ونص الدفع، وارجع إليها فورًا إذا ظهر عدم تطابق في checkout أو رسائل العميل. أي تفعيل Live للدفع أو تغيير أسعار أو مخزون بكميات كبيرة يحتاج موافقة المالك الصريحة.

## الخطوات التالية

أول خطوة تشغيلية هي أن يملأ مالك المتجر قالب SKU لكل منتج، ثم يضبط إعدادات الشحن والإرجاع والدفع في لوحة «إعدادات المتجر». بعد اختيار مزود الدفع والتحليلات يمكن تنفيذ تكاملين منفصلين مع Test Mode واختبارات قبول قبل الإطلاق العام.
